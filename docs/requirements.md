# 研究室用LLMチャットボット 要件定義書

- 文書バージョン: 1.0
- 作成日: 2026-07-12
- ステータス: ドラフト

## 1. 目的・背景

研究室内のユーザーが利用できるLLMチャットボットを構築する。本システムの目的は、単にチャット機能を提供することではなく、**ユーザーがLLMに対してどのような入力を行い、どのような出力が返されているかをデータとして蓄積・解析できるようにすること**にある。そのため、全ての入出力ログをデータベースに記録し、管理者が利用状況を分析できるダッシュボードを備える。

また、外部LLM APIの利用コストを抑えるため、研究室メンバー全員の利用量を合算しても無料枠に収まるよう、システム側で利用量を制御する。

## 2. 用語定義

| 用語 | 説明 |
|---|---|
| ユーザー | 研究室に所属し、本システムを利用する個人。ログインIDで識別される。 |
| 管理者 | アカウント管理・利用統計の閲覧権限を持つユーザー。 |
| ログインID | ユーザーを一意に識別するID（本システムではメールアドレスを兼用）。 |
| 無料枠 | Google Gemini APIの無料利用枠（リクエスト数/分・日、トークン数などの上限）。 |
| 利用ログ | チャットの入出力内容、トークン数、日時などを記録したレコード。 |

## 3. システム構成概要（技術スタック）

| 項目 | 選定内容 |
|---|---|
| フレームワーク | Next.js（TypeScript）フルスタック（App Router） |
| データベース | PostgreSQL |
| ORM | Prisma |
| LLM API | Google Gemini API |
| 認証 | 自前実装（メール＋パスワード、セッションCookie） |
| メール配信 | Resend（アカウント確認メール・パスワード変更通知メール） |
| グラフ描画（管理画面） | Recharts等 |
| ホスティング想定 | 研究室内サーバー or クラウド（Docker運用を想定） |

利用率・統計量は、チャット実行の都度「利用ログ（UsageLog）」としてDBに記録し、管理画面からSQL集計（Prismaのgroupby/集計クエリ）で表示する方式とする。

## 4. 機能要件

### 4.1 ユーザー認証機能

- FR-01: ユーザーはメールアドレス（ログインID）とパスワードでログインできる。
- FR-02: 新規アカウント作成時、ユーザーはメールアドレスを入力する。入力されたメールアドレス宛に確認メールを送信し、メール内のリンクをクリックすることでアカウントが有効化される（メールアドレスの実在確認）。
- FR-03: 未確認（メール未認証）のアカウントはログインできない。
- FR-04: 確認メールの有効期限（例: 24時間）を設け、期限切れの場合は再送できる。
- FR-05: ログイン失敗時は具体的な理由（未登録／パスワード誤り／未確認）を過度に開示しない一般的なエラーメッセージを返す。

### 4.2 パスワード変更機能

- FR-06: ログイン中のユーザーは現在のパスワードを入力した上で、新しいパスワードに変更できる。
- FR-07: パスワードを忘れた場合、登録メールアドレス宛にパスワード再設定用リンクを送信できる（有効期限付きトークン）。
- FR-08: パスワード変更が行われた場合、登録メールアドレスに変更通知メールを送信する。
- FR-09: パスワードは一定の強度基準（最小文字数など）を満たす必要がある。

### 4.3 チャット機能

- FR-10: ログイン済みユーザーはチャット画面からLLM（Gemini API）に対してメッセージを送信し、応答を受け取れる。
- FR-11: 過去の会話（自分のチャット履歴）を確認できる。
- FR-12: チャットの入力・出力内容、送信日時、ユーザーID、トークン数を全て利用ログとしてDBに保存する。

### 4.4 利用制限機能

- FR-13: システムはユーザー全体の合計利用量（リクエスト数／分・日、トークン数）を把握し、Gemini APIの無料枠上限に達しないよう制御する。
- FR-14: 無料枠の上限に近づいた場合、新規リクエストを制限（キューイングまたは拒否）し、ユーザーにその旨を通知する。
- FR-15: ユーザー単位でも1日あたりのメッセージ送信数・トークン数の上限を設け、公平な利用を確保する（上限値は管理画面から設定変更可能）。
- FR-16: 各種上限値（全体レート制限、ユーザー別上限）は設定ファイルまたは管理画面から変更できる。

### 4.5 管理画面機能

- FR-17: 管理者権限を持つユーザーのみアクセスできる管理画面を用意する。
- FR-18: 管理画面では、登録済みアカウントの一覧（ログインID、氏名、登録日、メール確認状態、最終ログイン日時等）を確認できる。
- FR-19: 管理画面では、利用統計ダッシュボードを表示する。最低限、以下の指標を可視化する。
  - 日別・週別・月別のリクエスト数／トークン使用量の推移
  - ユーザー別の利用量ランキング
  - 無料枠上限に対する現在の消費率
  - チャット内容のサンプル閲覧（入力・出力の内容確認）
- FR-20: 管理者はアカウントの有効化／無効化（利用停止）を行える。

## 5. 非機能要件

- NFR-01: パスワードはハッシュ化（bcrypt等）して保存し、平文では保持しない。
- NFR-02: セッション管理はCookieベースとし、CSRF対策を行う。
- NFR-03: 管理画面へのアクセスは管理者権限のロールチェックを行う（一般ユーザーはアクセス不可）。
- NFR-04: メール送信失敗時はリトライまたはエラーログを記録する。
- NFR-05: 利用ログは長期間の分析に耐えるよう、削除せず蓄積する（個人情報の取り扱いには十分配慮する）。
- NFR-06: APIキー等の機密情報は環境変数で管理し、リポジトリにコミットしない。
- NFR-07: レート制限判定は同時アクセス時にも正確に機能するよう、DBトランザクションまたはアトミックなカウンタで実装する。

## 6. データモデル概要

- User（id, email, passwordHash, name, role[USER/ADMIN], emailVerifiedAt, isActive, createdAt）
- VerificationToken（id, userId, token, type[EMAIL_VERIFY/PASSWORD_RESET], expiresAt, usedAt）
- Conversation（id, userId, title, createdAt）
- Message（id, conversationId, role[user/assistant], content, createdAt）
- UsageLog（id, userId, messageId, promptTokens, completionTokens, totalTokens, createdAt）
- RateLimitConfig（key, dailyRequestLimit, dailyTokenLimit, globalRpmLimit, ...）

## 7. 画面一覧

| 画面 | 概要 |
|---|---|
| ログイン画面 | メールアドレス／パスワードでログイン |
| アカウント作成画面 | メールアドレス入力→確認メール送信 |
| メール確認完了画面 | 確認リンク経由でアカウント有効化 |
| パスワード再設定申請画面 | 登録メールアドレスを入力 |
| パスワード再設定画面 | 新パスワード入力（トークン経由） |
| パスワード変更画面（マイページ） | ログイン中に現パスワード→新パスワード変更 |
| チャット画面 | LLMとの対話、履歴表示 |
| 管理画面：アカウント一覧 | ユーザー一覧・有効化/無効化 |
| 管理画面：利用統計ダッシュボード | 利用率等のグラフ表示 |

## 8. 前提条件・制約事項

- Google Gemini APIの無料枠の具体的な数値（RPM/RPD/TPM）はAPI仕様の変更があり得るため、システム側では設定値として外部化し、実際の枠に合わせて調整可能とする。
- 研究室内での利用を想定し、大規模な同時アクセスは想定しない。
- 対応言語は日本語UIを基本とする。

## 9. スコープ外（今回の対象外）

- 多要素認証（MFA）
- ソーシャルログイン（Google/GitHub等によるOAuthログイン）
- LLMのファインチューニング・独自モデルホスティング
- モバイルアプリ対応（レスポンシブWebのみ対応）
