# 要件定義書：研究用コーディングエージェント（VS Code拡張）とログ収集・管理基盤

- 版：v1.0（ドラフト）
- 作成日：2026-10-25
- 前提資料：[research-questions.md](../00_context/research-questions.md)（RQの正本）、[research-context.md](../00_context/research-context.md)
- 状態：研究者レビュー待ち。マージ後に実装に着手する

## 1. 目的と背景

研究室メンバー（以下「参加者」）に、Gemini API を使うコーディングエージェントを **VS Code 拡張機能** として配布し、普段の開発の中で利用してもらう。
研究者（以下「管理者」）は、参加者の利用ログをクラウド上のサーバーで自動収集し、管理画面から参加者ごと・全体の利用を任意に停止できる。

- 研究上の目的：RQ1〜RQ7（人間とAIの行動の種類・連鎖・期間を通じた変化）の分析に必要なイベントログを、参加者の提出作業なしで収集する
- 副次目的：有料契約者が少ない研究室に、共通のAI開発環境を提供する
- エージェントを自作することで、市販製品では観測しづらい **承認／拒否／修正指示／中断** などの人間の行動を確実に記録できる（research-context.md §4「取得可能と実証できた項目だけ」の制約を満たしやすい）

## 2. スコープ

### 2.1 対象（今回の開発で作るもの）

| 構成要素 | 概要 |
|---|---|
| A. VS Code 拡張機能（Agent Extension） | チャットパネル型のコーディングエージェント。ファイル閲覧・編集・コマンド実行をツールとして持ち、編集と実行は参加者の承認を経て行う。イベントを記録しサーバーへ送る |
| B. 研究用サーバー（Research API） | Gemini API の中継（APIキーはサーバーのみが保持）、参加者認証、利用可否判定、イベント受信・保存 |
| C. 管理画面（Admin Console） | 参加者の登録・招待コード発行・停止／再開、全体停止、収集状況の確認、ログ閲覧・CSV出力 |
| D. 研究用DB | PostgreSQL。イベントログ、参加者（研究用IDのみ）、設定 |

### 2.2 対象外

- 実際の参加者への配布、本番環境（クラウド）へのデプロイ、実データの収集開始（AGENTS.md「絶対に守ること」。教授の合意・倫理手続の完了後に別途実施）
- 独自エディタ（VS Code フォーク等）の開発
- 分析スクリプト（SQL・Python）。ログの出力形式（CSV）までを対象とする
- Unity エディタ内での直接利用（Unity プロジェクトを VS Code で開いて使うことは可能）
- VS Code Marketplace への公開（`.vsix` ファイルの配布を想定）

## 3. 全体構成

```
参加者PC（Windows / macOS）
  VS Code
   └ Agent Extension
       ├ チャットUI（Webview）
       ├ エージェントループ（Gemini の function calling）
       ├ ツール：read_file / list_files / search_files / edit_file / write_file / run_command
       ├ イベント記録 → ローカルバッファ（拡張のストレージ内ファイル）
       └ HTTPS ──────────────────────────────┐
                                              ▼
クラウド（Cloud Run 想定。Docker コンテナで提供）
  Research API ──▶ Gemini API（管理者が発行したAPIキー）
   ├ /api/v1/...（拡張向け）
   ├ /admin/...（管理画面、管理者ログイン必須）
   └ PostgreSQL（Cloud SQL / Neon 等のマネージドDB想定）

管理者
  ブラウザ → 管理画面（参加者管理・停止・ログ確認・CSV出力）
```

- 拡張機能は Gemini API に直接アクセスしない。すべての LLM 呼び出しは Research API を経由する
  - APIキーを参加者端末に置かない（抜き取り・流用の防止）
  - サーバー側で利用可否を判定できる（＝管理者による任意の停止が確実に効く）
  - 利用量（トークン数）をサーバーで集計・上限管理できる

## 4. 利用者と役割

| 利用者 | できること |
|---|---|
| 参加者 | 招待コードで拡張を有効化、同意の選択・変更、エージェントの利用、ログ収集の一時停止／再開、本文提供同意の撤回 |
| 管理者（研究者1名を想定） | 参加者の登録・停止・再開・削除、全体停止、モデル・利用上限の設定、ログの閲覧・CSV出力 |

## 5. 機能要件

### 5.1 拡張機能：導入・認証・同意

| ID | 要件 |
|---|---|
| FR-01 | 参加者は `.vsix` ファイルから拡張をインストールできる。サーバーURLは拡張の設定項目で、既定値をビルド時に埋め込める |
| FR-02 | 初回起動時に招待コード（管理者が発行）を入力すると、サーバーから参加者トークンが発行され、VS Code の SecretStorage に保存される。以降の通信はこのトークンで認証する |
| FR-03 | 有効化の直後に同意画面を表示する。同意項目は次の3つを **個別に** 選択でき、①以外は任意とする。<br>① 環境（エージェント）の利用 ② 研究へのメタデータログ提供 ③ 研究への本文（プロンプト・AI回答）提供 |
| FR-04 | 参加者はいつでもコマンド／設定画面から同意内容を変更できる。変更はサーバーに即時反映され、以降のイベントに適用される |
| FR-05 | ②③に同意しなくてもエージェントは利用できる（不参加・撤回で不利益を生じさせない） |

### 5.2 拡張機能：コーディングエージェント

| ID | 要件 |
|---|---|
| FR-10 | サイドバーのチャットパネルで、自然言語で依頼を入力し、AIの回答をストリーミング表示する（Markdown・コードブロック表示） |
| FR-11 | エージェントは Gemini の function calling で次のツールを使える。対象は開いているワークスペース内に限る<br>・`read_file`（ファイル内容の取得）・`list_files`（一覧）・`search_files`（文字列検索）<br>・`edit_file`（部分置換）・`write_file`（新規作成・上書き）・`run_command`（シェルコマンド実行） |
| FR-12 | `edit_file`・`write_file`・`run_command` は実行前に参加者へ提示し、**承認／拒否／修正指示付きで拒否** を選ばせる。ファイル変更は VS Code の差分ビューで確認できる |
| FR-13 | 参加者は設定で「ファイル編集を自動承認」を選べる（コマンド実行は常に承認必須）。自動承認かどうかもイベントに記録する |
| FR-14 | 参加者は生成・ツール実行を途中で中断できる |
| FR-15 | 「新しい会話」ボタンで会話をリセットできる。会話履歴は参加者端末内に保存し、パネルを閉じても直近の会話を再表示できる |
| FR-16 | 1回の依頼で連続するツール呼び出しには上限（既定 25 回）を設け、超えた場合は参加者に継続を確認する |
| FR-17 | ワークスペース外のパス、`.env` 等の秘密情報ファイルへのアクセスはツール側で拒否する（拒否リストは設定で変更可） |

### 5.3 拡張機能：ログ記録・送信

| ID | 要件 |
|---|---|
| FR-20 | 6章のイベントを記録し、ローカルバッファ（拡張のグローバルストレージ内のファイル）に追記する |
| FR-21 | バッファは一定間隔（既定 30 秒）または一定件数ごとにサーバーへ一括送信する。失敗時は指数バックオフで再送し、オフライン中も蓄積を続ける |
| FR-22 | 各イベントは UUID を持ち、サーバー側で重複排除する（再送しても二重登録されない） |
| FR-23 | ステータスバーに収集状態（収集中／一時停止中／利用停止中／未送信件数）を表示する |
| FR-24 | 参加者はステータスバーまたはコマンドで **収集を一時停止／再開** できる。一時停止中のイベントは記録自体を行わない（バッファにも残さない） |
| FR-25 | ②に同意していない場合、イベントは記録しない。③に同意していない場合、本文フィールドを記録しない（端末外に送信しない） |

### 5.4 サーバー：中継・停止制御

| ID | 要件 |
|---|---|
| FR-30 | `POST /api/v1/activate`：招待コードを受け取り、参加者トークンを発行する。招待コードは1回限り有効 |
| FR-31 | `GET /api/v1/status`：利用可否（参加者単位・全体）、同意状態、モデル名、拡張の最低バージョンなどを返す |
| FR-32 | `POST /api/v1/chat`：拡張からの会話内容とツール定義を受け、Gemini API を呼び出して結果をストリーミングで返す。APIキーは環境変数／Secret Manager から読み込む |
| FR-33 | 停止判定：参加者が「停止」状態、または全体停止中の場合、`/chat` は 403 を返し Gemini を呼ばない。拡張は「管理者により利用が停止されています」と表示し、入力欄を無効化する |
| FR-34 | 拡張は起動時・依頼送信時・定期（既定 5 分）に `/status` を確認し、停止状態を UI に反映する。停止が解除されたら再び利用可能になる |
| FR-35 | 参加者ごとの1日あたりトークン上限・リクエスト上限を設定でき、超過時は 429 を返す（費用上限の担保） |
| FR-36 | `POST /api/v1/events`：イベントの一括受信。参加者トークンで認証し、同意状態に反する項目（未同意の本文など）はサーバー側でも破棄する |
| FR-37 | `/chat` の中継時、サーバーはプロンプト・回答の本文を **保存しない**（研究用の本文保存は FR-36 のイベント経由・同意者のみに一本化する） |

### 5.5 管理画面

| ID | 要件 |
|---|---|
| FR-40 | 管理者はパスワードでログインする（パスワードはハッシュで環境変数に設定）。セッションは HttpOnly Cookie |
| FR-41 | 参加者一覧：研究用ID、状態（招待中／有効／停止／撤回）、同意状態、最終通信時刻、拡張バージョン、直近7日のイベント数・トークン使用量 |
| FR-42 | 参加者の登録（研究用IDを自動採番 例 `P001`）と招待コードの発行・再発行 |
| FR-43 | 参加者単位の **停止／再開**、および **全体停止／再開**（キルスイッチ）。操作は即時に `/chat` に反映される |
| FR-44 | 参加者の削除（撤回時）：その参加者のイベントを全削除できる。削除は確認ダイアログを経る |
| FR-45 | ログ閲覧：参加者・期間・イベント種別で絞り込み、時系列で表示する |
| FR-46 | CSV 出力：絞り込み条件に一致するイベントを CSV でダウンロードできる（分析用） |
| FR-47 | 設定：使用モデル名、1日あたり上限、拡張の最低バージョン |
| FR-48 | 収集の正常性：参加者ごとに最終受信時刻を表示し、一定期間（既定 3 日）受信がない参加者を強調表示する |

## 6. データ要件（収集するイベント）

### 6.1 共通項目

| 項目 | 内容 |
|---|---|
| event_id | UUID（重複排除用） |
| participant_id | 研究用ID（サーバーがトークンから付与。拡張は送らない） |
| session_id | VS Code ウィンドウ起動ごとのID |
| conversation_id | チャットの会話ID（「新しい会話」で更新） |
| turn_index | 会話内での人の入力の通し番号 |
| type | イベント種別（6.2） |
| occurred_at | 発生時刻（端末時刻、UTC） |
| received_at | サーバー受信時刻 |
| extension_version / vscode_version / os | 環境情報（OS は `win32` / `darwin` 等の種別のみ） |
| payload | 種別ごとの項目（JSON） |

### 6.2 イベント種別

| type | 発生タイミング | payload（メタデータ：②同意で記録） | 本文（③同意時のみ） |
|---|---|---|---|
| `session_start` / `session_end` | 拡張の起動・終了 | ワークスペースの有無 | — |
| `conversation_start` | 新しい会話 | — | — |
| `user_prompt` | 人の入力（依頼・修正指示・追加質問） | 文字数、直前のAI出力からの経過時間 | 入力本文 |
| `model_response` | AIの1回の応答完了 | 文字数、出力タイプ（テキスト／ツール呼び出し／混在）、ツール呼び出し数、所要時間、入出力トークン数、モデル名 | 回答本文（テキスト部分） |
| `tool_call` | AIがツール呼び出しを提案 | ツール名、承認が必要か | — |
| `tool_decision` | 人が承認／拒否 | 決定（approved / rejected / rejected_with_feedback / auto_approved）、判断までの時間 | 修正指示の本文 |
| `tool_result` | ツール実行完了 | ツール名、成否、所要時間、変更行数（追加／削除）、コマンドの終了コード | — |
| `user_cancel` | 人が生成・実行を中断 | 中断時の状態 | — |
| `error` | API エラー・上限超過・停止による拒否 | エラー種別、HTTPステータス | — |
| `consent_changed` / `collection_paused` / `collection_resumed` | 同意変更・一時停止・再開 | 変更後の状態 | — |

### 6.3 収集しない項目

- ツールが読み書きしたファイルの内容、ファイル名、パス、検索文字列
- コマンド文字列とその出力
- 認証情報、環境変数
- 上記は③の同意があっても収集しない（本文の対象は「人の入力」「AIの回答テキスト」「修正指示」に限る）

### 6.4 分析単位との対応（参考）

- ターン：`user_prompt` → `model_response`／`tool_call`… → 次の `user_prompt` または `tool_decision`
- エピソード：`conversation_id` と時間ギャップ（research-context.md §3）で分析時に判定する。収集側では判定しない
- 人間の行動（RQ1）：`tool_decision` の決定種別、`user_cancel`、`user_prompt`（本文同意者は内容で修正指示／追加質問を分類可能）
- 成果物の作成過程（RQ4〜7）：`tool_result` の変更行数・成否・コマンド終了コードの集計

## 7. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | 拡張は Windows / macOS の VS Code（1.90 以降）で動作する |
| NFR-02 | 通信はすべて HTTPS（本番）。参加者トークン・管理者パスワードはハッシュでDBに保存する |
| NFR-03 | Gemini APIキー・DB接続情報・管理者パスワードはリポジトリに含めず、環境変数で与える（`.env.example` を用意） |
| NFR-04 | サーバーは Docker イメージとして提供し、Cloud Run 等のコンテナ実行環境にそのままデプロイできる |
| NFR-05 | 停止操作から拡張の利用不可までの反映は、次の依頼送信時に即時（`/chat` が拒否）、UI 表示は最大 5 分以内 |
| NFR-06 | ログ送信の失敗・オフラインでもエージェントの利用は妨げない。バッファは上限（既定 10,000 件）を超えたら古いものから破棄し、破棄件数を記録する |
| NFR-07 | 研究用IDと氏名の対応表はシステムに保存しない（管理者が別途保管する。仮名化） |
| NFR-08 | 主要ロジック（エージェントループ、同意によるフィルタ、停止判定、重複排除）に自動テストを用意する |

## 8. プライバシー・研究倫理

- 本文（③）の保存は、research-context.md §4 の「初期試行では中央に送信しない」から方針を変更するものである。**実データの収集前に教授の合意・倫理手続で承認を得ること**（システム側は既定で本文を送らず、同意者のみ送る設計で AGENTS.md の「既定設定で送信しない」を満たす）
- 参加者のコードは、エージェント利用時に Gemini API（Google）へ送信される。これは「環境の利用」に伴う送信であり、同意画面①で明示する。Gemini API は **有料枠（課金設定済みプロジェクト）のキーを使う**こと（無料枠では入力が Google の製品改善に利用されうる）
- 管理者による「利用停止」と、参加者による「収集の一時停止」は別機能として提供し、同意画面で説明する
- 報告は原則集計値とし、個々の利用内容を評価・監督に使わない（運用ルール。システム外）

## 10. 受け入れ条件（実装PRの完了条件）

1. ローカルでサーバー（＋PostgreSQL）を起動し、管理画面で参加者を登録・招待コードを発行できる
2. 拡張を開発ホスト（または `.vsix`）で起動し、招待コードで有効化・同意選択ができる
3. チャットで依頼すると、Gemini（APIキー未設定時はテスト用のモック）経由で回答が返り、ファイル編集・コマンド実行が承認フロー付きで動く
4. 6章のイベントがサーバーに届き、同意状態に応じて本文の有無が切り替わる。管理画面で閲覧・CSV出力できる
5. 管理画面で参加者を停止すると、拡張からの依頼が拒否され「利用停止」と表示される。全体停止も同様。再開で復帰する
6. 収集の一時停止中はイベントが記録されない
7. Lint・型チェック・テスト・ビルドが通り、手順を README／AGENTS.md に記載している
8. クラウドへのデプロイ手順書（Cloud Run 想定）を `01_docs/` に置く（デプロイ自体は行わない）

## 11. 未決事項・研究者に確認したい点

| # | 論点 | 現在の案 |
