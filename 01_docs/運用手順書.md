# 運用手順書（研究者向け）

実験期間中に研究者が行う作業の手順をまとめる。ほとんどの作業は管理画面で行う。

## 1. 管理画面に入る

1. ブラウザで `https://<サーバーURL>/admin` を開く
2. 「Google でログイン」を押し、管理者として登録したアカウントを選ぶ
3. 上部のメニューで「参加者」「ログ」「設定」を切り替える

サーバーURLは次のコマンドで確認できる。

```bash
gcloud run services describe research-llm --project research-llm-512715 --region asia-northeast1 --format="value(status.url)"
```

## 2. 参加者を追加する

1. 「参加者」画面の「○人分の招待コードを発行」に人数を入れ、「発行」を押す
2. 「発行した招待コード」に研究用IDと招待コードが表示される。**この画面を閉じると招待コードは二度と表示されない**ので、すぐに控える
3. 研究用IDと氏名の対応を、システムの外（研究ログとは別の場所）に記録する
4. 配布パッケージ（ZIP）と招待コードを、参加者ごとに個別に渡す

## 3. 参加者の様子を確認する

「参加者」画面で、参加者ごとに状態・同意の内容・最終接続・最終ログ受信・直近24時間のログ件数・利用回数・拡張機能の版を確認できる。

- 3日以上ログが届いていない参加者は、最終ログ受信が赤字で表示される。PC の不調やインストールの問題がないか、本人に確認する
- 研究用IDを押すと、その参加者のログだけを表示できる

## 4. 特定の参加者の利用を止める・再開する

1. 「参加者」画面で対象の行の「停止」を押す。次の依頼から使えなくなる
2. 再開するときは、同じ行の「再開」を押す

## 5. 全員の利用を止める（緊急時）

不具合や API キーの問題など、すぐに全員を止めたいときに使う。

1. 「参加者」画面の上部にある「全体の利用を停止」を押し、確認画面で OK を押す
2. 状態が「全体停止中」になる
3. 問題が解決したら「全体の利用を再開」を押す

## 6. PC を変えた参加者に招待コードを出し直す

1. 「参加者」画面で対象の行の「コード再発行」を押す
2. 新しい招待コードが表示されるので控えて、本人に渡す。古い PC からの接続はこの時点で使えなくなる

## 7. 同意を撤回した参加者に対応する

参加者が拡張機能で同意を撤回すると、状態が「撤回」になり、利用できなくなる。

- 撤回時にデータの削除を求めた参加者は「削除依頼あり」と表示される。この場合は 8 章の手順でデータを削除する
- 本人から再開の希望があった場合は、対象の行の「再開」を押す。参加者が拡張機能で改めてすべてに同意すると、再び使えるようになる

## 8. 参加者のデータを削除する

削除依頼があったときに行う。元に戻せない。

1. 「参加者」画面で対象の行の「削除」を押し、確認画面で OK を押す
2. その参加者の情報と、すべてのログが削除される
3. システム外で管理している研究用IDと氏名の対応表からも、その参加者を消す

## 9. ログを見る・CSV で取り出す

1. 「ログ」画面で、参加者・種別・期間を選んで「絞り込み」を押す。新しい順に表示される
2. 「CSV ダウンロード」で出力したい列にチェックを入れ、「CSV をダウンロード」を押す。上の絞り込み条件のまま出力される

本文・拡張子・トークン数・添付画像IDは、初期状態では出力されない。必要なときだけチェックを入れる。

参加者が依頼に添付した画像は、ログ一覧の本文の欄にある「添付画像1」などのリンクから開ける。

## 10. 利用上限・モデルを変える

1. 「設定」画面で値を変え、「保存」を押す
2. 1日の区切りは太平洋時間の 0 時（日本時間の 16 時か 17 時）。Gemini の無料枠がリセットされる時刻に合わせている

モデルの初期値は `gemini-3.5-flash`（1回の応答が数秒）。以前の `gemini-2.5-flash` は、新しく作った API キーでは使えなくなっている（使うと依頼がすべて「サーバーでエラーが発生しました（502）」になる）。`gemini-3.8-flash` は使えるが、2026-11-02 の試験では1回の応答に 1〜4 分かかり、エージェントが止まったように見えた。

利用上限の初期値（全体 10 回/分・250 回/日、1人 80 回/日・200 万トークン/日）は、以前の `gemini-2.5-flash` の無料枠に合わせて決めた値。今のモデルの無料枠と合っているか https://ai.google.dev/gemini-api/docs/rate-limits で確認して調整する。

## 11. サーバーを更新する

サーバーのコードを変えたときに行う。Cloud Shell か、gcloud が使える端末で実行する。

1. 今の設定値を確認する
   ```bash
   gcloud run services describe research-llm --project research-llm-512715 --region asia-northeast1 --format="yaml(spec.template.spec.containers[0].env)"
   ```
2. 表示された `ADMIN_EMAILS` と `GOOGLE_CLIENT_ID` を付けてデプロイする（シークレットは登録済みなので入力は求められない）
   ```bash
   ADMIN_EMAILS="..." GOOGLE_CLIENT_ID="..." ./02_scripts/deploy/deploy.sh
   ```

`GOOGLE_CLIENT_ID` を付け忘れると、管理画面にログインできなくなる。

## 12. 拡張機能を更新して配り直す

1. `02_scripts/extension/package.json` の `version` を上げる
2. 配布パッケージを作る
   ```bash
   ./02_scripts/deploy/build-distribution.sh https://<サーバーURL>
   ```
3. `02_scripts/deploy/out/research-llm-agent-<版>.zip` ができるので、参加者に配る（中身は `.vsix`・インストール用ファイル・参加者向け手順書。サーバーURLは埋め込み済みなので、参加者の設定は不要）
4. 古い版を使わせたくない場合は、「設定」画面の「最低拡張バージョン」を新しい版に上げる。古い版の利用者には更新を求める画面が出る

## 参考：システムの構成

- サーバー（参加者用 API と管理画面）：`02_scripts/server/`。Cloud Run（`asia-northeast1`、サービス名 `research-llm`）で動かしている。1分あたりの上限をサーバー内で数えるため、インスタンスは最大 1 台
- データベース：Firestore。ログは受信から 1 年で自動的に削除される
- 秘密情報：Secret Manager（Gemini API キー、セッション用の鍵、OAuth クライアントシークレット）
- 拡張機能：`02_scripts/extension/`
- ローカルでの開発・確認の方法は [AGENTS.md](../AGENTS.md) の「開発コマンド」を参照。`GEMINI_API_KEY` が空ならモック応答になり、`ADMIN_DEV_LOGIN=1` でメールアドレスを入れるだけのローカル用ログインが使える（本番では無効）
