## 1. 目的と背景

研究室メンバー（以下「参加者」）に、Gemini API を使うコーディングエージェントを **VS Code 拡張機能** として配布し、普段の開発の中で利用してもらう。
研究者（以下「管理者」）は、参加者の利用ログを GCP 上のサーバーで自動収集し、管理画面から参加者ごと・全体の利用を任意に停止できる。

- 研究上の目的：RQ1〜RQ7（人間とAIの行動の種類・連鎖・期間を通じた変化）の分析に必要なイベントログを、参加者の提出作業なしで収集する
- 副次目的：有料契約者が少ない研究室に、共通のAI開発環境を提供する
- エージェントを自作することで、市販製品では観測しづらい **承認／拒否／修正指示／中断** などの人間の行動を確実に記録できる（研究コンテキスト.md §4「取得可能と実証できた項目だけ」の制約を満たしやすい）

### 1.1 対応する開発対象

エージェントは VS Code で開いたフォルダ内のファイルを読み書きし、コマンドを実行する。言語やフレームワークは問わない。

| 開発対象 | 使い方 | できないこと |
|---|---|---|
| 一般的な開発（Web、Python 等） | そのまま利用 | — |
| Unity | Unity プロジェクトを VS Code で開き、C# スクリプトの作成・修正に使う | Unity エディタの操作（Play、シーン・Prefab 編集）。実行・確認は Unity 側で行う |
| Processing | スケッチフォルダを VS Code で開き、`.pde` を編集。`processing-java` が入っていればコマンド実行でスケッチを起動できる | Processing IDE 内での利用 |

## 2. スコープ

### 2.1 対象（今回の開発で作るもの）

| 構成要素 | 概要 |
|---|---|
| A. VS Code 拡張機能（Agent Extension） | チャットパネル型のコーディングエージェント。ファイル閲覧・編集・コマンド実行をツールとして持ち、編集と実行は参加者の承認を経て行う。イベントを記録しサーバーへ送る |
| B. 研究用サーバー（Research API） | Gemini API の中継（APIキーはサーバーのみが保持）、参加者認証、利用可否判定、利用量の上限管理、イベント受信・保存 |
| C. 管理画面（Admin Console） | 参加者の登録・招待コード発行・停止／再開、全体停止、収集状況の確認、ログ閲覧・CSV出力 |
| D. 研究用DB | Firestore（GCP）。イベントログ、参加者（研究用IDのみ）、設定 |
| E. GCP への本番デプロイ | Cloud Run（B・C）、Firestore（D）、Secret Manager（APIキー等）。デプロイ手順書とスクリプトを含む |
| F. 配布パッケージ | `.vsix`（サーバーURL埋め込み済み）＋ Windows／macOS 用のインストールスクリプト ＋ 参加者向け手順書 |

### 2.2 対象外

- 参加者への実際の配布と実データの収集開始（研究者が判断して実施する。教授の合意は取得済みで、倫理手続の書類は必要に応じて後日作成する）
- 独自エディタ（VS Code フォーク等）の開発、研究室サーバーの利用
- 分析スクリプト（SQL・Python）。ログの出力形式（CSV）までを対象とする
- Unity エディタ・Processing IDE 内での直接利用（1.1 のとおり VS Code 経由で利用する）
- VS Code Marketplace への公開

## 3. 全体構成

```
参加者PC（Windows / macOS）
  VS Code
   └ Agent Extension（.vsix）
       ├ チャットUI（Webview）
       ├ エージェントループ（Gemini の function calling）
       ├ ツール：read_file / list_files / search_files / edit_file / write_file / run_command
       ├ イベント記録 → ローカルバッファ（拡張のストレージ内ファイル）
       └ HTTPS ──────────────────────────────┐
                                              ▼
GCP プロジェクト（research-llm-512715）
  Cloud Run：Research API（Docker コンテナ）
   ├ /api/v1/...（拡張向け）           ──▶ Gemini API（管理者が発行した1つのAPIキーを全参加者で共有）
   ├ /admin/...（管理画面、管理者ログイン必須）
   ├ Secret Manager（Gemini APIキー、OAuth クライアントシークレット、セッション署名鍵）
   └ Firestore（イベント・参加者・設定。TTL で 1 年後に自動削除）

管理者
  ブラウザ → 管理画面（参加者管理・停止・ログ確認・CSV出力）
```

- 拡張機能は Gemini API に直接アクセスしない。すべての LLM 呼び出しは Research API を経由する
  - APIキーを参加者端末に置かない（抜き取り・流用の防止）
  - サーバー側で利用可否を判定できる（＝管理者による任意の停止が確実に効く）
  - 1つのAPIキーを共有するため、全体と参加者ごとの利用量をサーバーで集計・上限管理する
- 費用は GCP・Gemini API の無料枠内に収めることを目標とする（Cloud SQL は固定費がかかるため使わず Firestore を採用）

## 4. 利用者と役割

| 利用者 | できること |
|---|---|
| 参加者 | インストールスクリプトの実行と招待コードの入力、同意、エージェントの利用、ログ収集の一時停止／再開、同意の撤回（＝利用停止） |
| 管理者（研究者1名を想定） | 参加者の登録・停止・再開・削除、全体停止、モデル・利用上限の設定、ログの閲覧・CSV出力、GCP へのデプロイ |

## 5. 機能要件

### 5.1 拡張機能：導入・認証・同意

| ID | 要件 |
|---|---|
| FR-01 | 参加者は配布パッケージのインストールスクリプト（Windows：`install.cmd`、macOS：`install.command`）をダブルクリックするだけで拡張を導入できる。スクリプトは `code --install-extension` を実行する。`.vsix` を VS Code にドラッグ＆ドロップする方法も手順書に記載する |
| FR-02 | サーバーURLはビルド時に `.vsix` に埋め込み、参加者の設定作業を不要にする（設定項目で上書きは可能） |
| FR-03 | 初回起動時に招待コード（管理者が発行）を入力すると、サーバーから参加者トークンが発行され、VS Code の SecretStorage に保存される。以降の通信はこのトークンで認証する |
| FR-04 | 有効化の直後に同意画面を表示する。同意項目は ① 環境（エージェント）の利用と Gemini API へのデータ送信 ② 研究へのメタデータログ提供 ③ 研究への本文（人の入力・AI回答・修正指示）と添付画像の提供 の3つ。**①〜③すべての同意を利用の条件とする** |
| FR-05 | 参加者はいつでもコマンドから同意を撤回できる。撤回するとサーバー上の参加者状態が「撤回」になり、**エージェントは利用停止**になる（`/chat` が拒否される）。撤回後の再開は管理者が行う |
| FR-06 | 撤回時、参加者は「収集済みデータの削除を希望する」を選べる。希望は管理画面に表示され、管理者が FR-44 で削除する |

### 5.2 拡張機能：コーディングエージェント

| ID | 要件 |
|---|---|
| FR-10 | サイドバーのチャットパネルで、自然言語で依頼を入力し、AIの回答をストリーミング表示する（Markdown・コードブロック表示） |
| FR-10a | 依頼に画像（スクリーンショットなど）を添付できる。入力欄への貼り付け・「画像を添付」ボタン・ドラッグ＆ドロップに対応し、1回の依頼につき最大 4 枚。送信前に長辺 1568px 以下の JPEG に縮小する。画像は Gemini に送られ、本文への同意（③）がある場合は研究用ログとして保存する（FR-36a） |
| FR-11 | エージェントは Gemini の function calling で次のツールを使える。対象は開いているワークスペース内に限る<br>・`read_file`（ファイル内容の取得）・`list_files`（一覧）・`search_files`（文字列検索）<br>・`edit_file`（部分置換）・`write_file`（新規作成・上書き）・`run_command`（シェルコマンド実行） |
| FR-12 | `edit_file`・`write_file`・`run_command` は実行前に参加者へ提示し、**承認／拒否／修正指示付きで拒否** を選ばせる。ファイル変更は VS Code の差分ビューで確認できる |
| FR-13 | 参加者は設定で「ファイル編集を自動承認」を選べる（コマンド実行は常に承認必須）。自動承認かどうかもイベントに記録する |
| FR-14 | 参加者は生成・ツール実行を途中で中断できる |
| FR-15 | 「新しい会話」ボタンで会話をリセットできる。会話履歴は参加者端末内に保存し、パネルを閉じても直近の会話を再表示できる |
| FR-16 | 1回の依頼で連続するツール呼び出しには上限（既定 25 回）を設け、超えた場合は参加者に継続を確認する |
| FR-17 | ワークスペース外のパス、`.env` 等の秘密情報ファイルへのアクセスはツール側で拒否する（拒否リストは設定で変更可） |
| FR-18 | 上限超過（FR-35）時は「本日の利用上限に達しました（○時にリセット）」と表示する |

### 5.3 拡張機能：ログ記録・送信

| ID | 要件 |
|---|---|
| FR-20 | 6章のイベントを記録し、ローカルバッファ（拡張のグローバルストレージ内のファイル）に追記する |
| FR-21 | バッファは一定間隔（既定 30 秒）または一定件数ごとにサーバーへ一括送信する。失敗時は指数バックオフで再送し、オフライン中も蓄積を続ける |
| FR-22 | 各イベントは UUID を持ち、サーバー側で重複排除する（再送しても二重登録されない） |
| FR-23 | ステータスバーに状態（収集中／一時停止中／利用停止中／未送信件数）を表示する |
| FR-24 | 参加者はステータスバーまたはコマンドで **収集を一時停止／再開** できる（私用作業・第三者情報を含む作業向け）。一時停止中のイベントは記録自体を行わない。**一時停止中はエージェントを利用できない**（入力欄と送信を無効にし、実行中の依頼は中止する）。再開すると利用できる |

### 5.4 サーバー：中継・停止制御

| ID | 要件 |
|---|---|
| FR-30 | `POST /api/v1/activate`：招待コードを受け取り、参加者トークンを発行する。招待コードは1回限り有効 |
| FR-31 | `GET /api/v1/status`：利用可否（参加者単位・全体）、同意状態、モデル名、残り利用量、拡張の最低バージョンを返す |
| FR-32 | `POST /api/v1/consent`：同意・撤回を受け付け、撤回時は参加者状態を「撤回」にする |
| FR-33 | `POST /api/v1/chat`：拡張からの会話内容とツール定義を受け、Gemini API を呼び出して結果をストリーミングで返す。APIキーは Secret Manager（ローカルでは環境変数）から読み込む |
| FR-34 | 停止判定：参加者が「停止」「撤回」状態、未同意、または全体停止中の場合、`/chat` は 403 を返し Gemini を呼ばない。拡張は理由（管理者による停止／同意撤回）を表示し、入力欄を無効化する。拡張は起動時・依頼送信時・定期（既定 5 分）に `/status` を確認する |
| FR-35 | 利用量の上限：共有APIキーの無料枠に合わせ（既定値は実装時点の無料枠の公表値から決める）、**全体**の1分あたり・1日あたりリクエスト数、**参加者ごと**の1日あたりリクエスト数・トークン数を管理画面で設定できる。超過時は 429 を返す。Gemini 側が 429 を返した場合も同様に扱う |
| FR-36 | `POST /api/v1/events`：イベントの一括受信。参加者トークンで認証し、同意していない参加者からのイベントは破棄する |
| FR-36a | `user_prompt` に添付された画像は、本文への同意がある場合のみイベントとは別のコレクション（`attachments`）に保存し、イベントの本文に画像IDを残す。保存期間はイベントと同じ（NFR-08）。参加者の削除（FR-44）で一緒に削除する。管理画面のログ一覧から画像を開ける |
| FR-37 | `/chat` の中継時、サーバーはプロンプト・回答の本文を保存しない（研究用の本文保存は FR-36 のイベント経由に一本化する） |

### 5.5 管理画面

| ID | 要件 |
|---|---|
| FR-40 | 管理者は **Google アカウントでログイン** する（OAuth 2.0 / OpenID Connect）。メールアドレスが確認済みで、管理者リスト（環境変数 `ADMIN_EMAILS`、複数指定可）に含まれるアカウントのみログインを許可し、それ以外は 403 とする。管理者のメールアドレスはリポジトリに書かない。セッションは署名付き HttpOnly Cookie |
| FR-41 | 参加者一覧：研究用ID、状態（招待中／有効／停止／撤回）、同意状態、削除希望の有無、最終通信時刻、拡張バージョン、当日・直近7日のリクエスト数・トークン使用量 |
| FR-42 | 参加者の登録（研究用IDを自動採番 例 `P001`）と招待コードの発行・再発行 |
| FR-43 | 参加者単位の **停止／再開**、および **全体停止／再開**（キルスイッチ）。操作は即時に `/chat` に反映される |
| FR-44 | 参加者の削除：その参加者のイベントを全削除できる。削除は確認ダイアログを経る |
| FR-45 | ログ閲覧：参加者・期間・イベント種別で絞り込み、時系列で表示する |
| FR-46 | CSV 出力：参加者・期間・イベント種別で絞り込み、さらに **出力する列を管理者が選択** できる（本文、ファイル拡張子、トークン数など。既定はメタデータのみ）。データ量の肥大化を避けるため |
| FR-47 | 設定：使用モデル名（既定 `gemini-3.5-flash`。`gemini-2.5-flash` は新しい API キーでは使えず、`gemini-3.8-flash` は応答に数分かかることがあったため）、利用上限（FR-35）、拡張の最低バージョン |
| FR-48 | 収集の正常性：参加者ごとに最終受信時刻を表示し、一定期間（既定 3 日）受信がない参加者を強調表示する。全体の当日リクエスト数と上限も表示する |

## 6. データ要件（収集するイベント）

### 6.1 共通項目

| 項目 | 内容 |
|---|---|
| event_id | UUID（重複排除用） |
| participant_id | 研究用ID（サーバーがトークンから付与。拡張は送らない） |
| session_id | VS Code ウィンドウ起動ごとのID |
| conversation_id | チャットの会話ID（「新しい会話」で更新） |
| turn_index | 会話内での人の入力の通し番号 |
| type | イベント種別（6.2） |
| occurred_at | 発生時刻（端末時刻、UTC） |
| received_at | サーバー受信時刻 |
| expire_at | 削除予定時刻（received_at の 1 年後。Firestore TTL で自動削除） |
| extension_version / vscode_version / os | 環境情報（OS は `win32` / `darwin` 等の種別のみ） |
| payload | 種別ごとの項目（JSON） |

### 6.2 イベント種別

| type | 発生タイミング | payload（メタデータ） | 本文 |
|---|---|---|---|
| `session_start` / `session_end` | 拡張の起動・終了 | ワークスペースの有無 | — |
| `conversation_start` | 新しい会話 | — | — |
| `user_prompt` | 人の入力（依頼・修正指示・追加質問） | 文字数、添付画像数、直前のAI出力からの経過時間 | 入力本文、添付画像（FR-36a） |
| `model_response` | AIの1回の応答完了 | 文字数、出力タイプ（テキスト／ツール呼び出し／混在）、ツール呼び出し数、所要時間、入出力トークン数、モデル名 | 回答本文（テキスト部分） |
| `tool_call` | AIがツール呼び出しを提案 | ツール名、承認が必要か、対象ファイルの拡張子 | — |
| `tool_decision` | 人が承認／拒否 | 決定（approved / rejected / rejected_with_feedback / auto_approved）、判断までの時間 | 修正指示の本文 |
| `tool_result` | ツール実行完了 | ツール名、成否、所要時間、変更行数（追加／削除）、対象ファイルの拡張子、コマンドの終了コード | — |
| `user_cancel` | 人が生成・実行を中断 | 中断時の状態 | — |
| `error` | API エラー・上限超過・停止による拒否 | エラー種別、HTTPステータス | — |
| `consent_changed` / `collection_paused` / `collection_resumed` | 同意・撤回・一時停止・再開 | 変更後の状態 | — |

### 6.3 収集しない項目

- ツールが読み書きしたファイルの内容、ファイル名、パス（拡張子のみ収集）、検索文字列
- コマンド文字列とその出力
- 認証情報、環境変数

### 6.4 分析単位との対応（参考）

- ターン：`user_prompt` → `model_response`／`tool_call`… → 次の `user_prompt` または `tool_decision`
- エピソード：`conversation_id` と時間ギャップ（研究コンテキスト.md §3）で分析時に判定する。収集側では判定しない
- 人間の行動（RQ1）：`tool_decision` の決定種別、`user_cancel`、`user_prompt` の本文（修正指示／追加質問などに分類）
- 成果物の作成過程（RQ4〜7）：`tool_result` の変更行数・成否・拡張子・コマンド終了コードの集計

## 7. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | 拡張は Windows / macOS の VS Code（1.90 以降）で動作する |
| NFR-02 | 通信はすべて HTTPS。参加者トークンはハッシュで保存する |
| NFR-03 | Gemini APIキー・OAuth クライアントシークレット・署名鍵はリポジトリに含めない。本番は Secret Manager、ローカルは `.env`（`.env.example` を用意） |
| NFR-04 | サーバーは Docker イメージとして Cloud Run にデプロイする。デプロイはスクリプト（`gcloud`）1本で再現できる |
| NFR-05 | 停止操作は次の依頼送信時に即時反映（`/chat` が拒否）、UI 表示は最大 5 分以内 |
| NFR-06 | ログ送信の失敗・オフラインでもエージェントの利用は妨げない。バッファは上限（既定 10,000 件）を超えたら古いものから破棄し、破棄件数を記録する |
| NFR-07 | 研究用IDと氏名の対応表はシステムに保存しない（管理者が別途保管する。仮名化） |
| NFR-08 | データ保存期間は受信から **1 年**。Firestore の TTL ポリシーで自動削除する |
| NFR-09 | GCP（Cloud Run・Firestore・Secret Manager）と Gemini API の無料枠内での運用を目標とする。Cloud Run は最小インスタンス 0 |
| NFR-10 | 主要ロジック（エージェントループ、同意・停止判定、上限管理、重複排除、CSV 列選択）に自動テストを用意する。DB はインターフェースで抽象化し、テスト・ローカル開発ではメモリ実装を使えるようにする |

## 8. プライバシー・研究倫理（リスクと対応）

## 9. 技術スタック

| 対象 | 採用 | 理由 |
|---|---|---|
| 拡張機能 | TypeScript、VS Code Extension API、Webview（素の HTML/CSS/TS）、esbuild、vsce | 公式手順で `.vsix` を作れる。ネイティブモジュールを使わず Windows/macOS 差を避ける |
| サーバー | Node.js 20+、TypeScript、Hono、Gemini 公式SDK（@google/genai） | 軽量でストリーミング応答が容易。管理画面も Hono の JSX でサーバーレンダリング |
| DB | Firestore（@google-cloud/firestore）。ローカル・テストはメモリ実装 | 無料枠があり固定費なし。TTL で 1 年削除を自動化できる |
| インフラ | Cloud Run、Secret Manager、Artifact Registry、`gcloud` によるデプロイスクリプト | GCP 内で完結。リージョンは asia-northeast1 |
| テスト・Lint | Vitest、ESLint、`tsc --noEmit` | 拡張・サーバー共通 |
| 配置 | `02_scripts/extension/`、`02_scripts/server/`、`02_scripts/deploy/` | AGENTS.md のフォルダ規約に従う |

## 10. 受け入れ条件（実装PRの完了条件）

1. ローカルでサーバーを起動し、管理画面で参加者を登録・招待コードを発行できる
2. 拡張を `.vsix` からインストールし、招待コードで有効化・同意ができる
3. チャットで依頼すると Gemini 経由で回答が返り、ファイル編集・コマンド実行が承認フロー付きで動く
4. 6章のイベントがサーバーに届き、管理画面で閲覧でき、列を選んで CSV 出力できる
5. 管理画面で参加者を停止すると拡張からの依頼が拒否され「利用停止」と表示される。全体停止も同様。再開で復帰する
6. 参加者が同意を撤回すると利用停止になり、管理画面に「撤回」と表示される
7. 収集の一時停止中はイベントが記録されず、エージェントも利用できない
8. 利用上限を超えると 429 となり、拡張に上限到達が表示される
9. GCP（Cloud Run＋Firestore＋Secret Manager）にデプロイされ、デプロイ先URLで 1〜8 が動作する（テスト用参加者で確認する）
10. 配布パッケージ（`.vsix`＋インストールスクリプト＋参加者向け手順書）と、デプロイ・運用手順書が `01_docs/` にある
11. Lint・型チェック・テスト・ビルドが通り、開発コマンドを AGENTS.md と `.devin/blueprint.yaml` に反映している
